## 二、这个项目做了什么


本项目在“做出一个能自己玩的贪吃蛇”的基础上，进一步让 AI 接管操作，实现连续吃满 15 个食物不死。相比最初的版本，我新增了这几项：

- **AI 自动游玩**：新增独立寻路模块 `ai.js`，点击后由 AI 接管方向，连续吃满 15 个食物视为挑战成功。加它的原因是纯玩家模式无法体现“用提示词驱动 AI 完成复杂逻辑”这一考核重点。
- **加速模式**：为了更加方便观察ai，只做了加速模式并提供按钮
- **计分制**：得分 = 10 × 吃到食物后的长度，并记录最高分与局数，新一局不清零，提供“重置”按钮。
- **多局战绩**：记录最近 10 局的模式、得分、长度、结果，新一局自动追加，可查看完整列表。
- **主题切换**：深色 / 浅色 / 粉色三套配色，一键切换即时生效，刷新后保留。

## 五、阶段二：AI 自动游玩怎么实现、怎么验证

**硬指标**：AI 自动控制蛇，连续吃完 15 个食物不死（不撞墙、不撞自己），全程无需人工操作。

**实现**（`ai.js`，每次决策只读一份快照，不碰 DOM、不改游戏状态）：

1. **BFS 找最短路**：从蛇头向食物搜四邻，蛇身为障碍，尾节视为可通过（头走到那里时尾巴通常已经移开）。
2. **路径逐步模拟**：沿候选路径逐格推演，按“这一步是否吃到食物”决定是否弹尾，检查每步新头是否出界或撞到当时的蛇身。
3. **吃完后的安全校验**：模拟吃到食物后的状态（长度 +1），用洪水填充判断“蛇头还能不能走到自己的尾巴”，能追到尾巴才说明不会被自己围死。
4. **保命兜底**：食物不可达或路径不安全时，比较四个方向的“尾可达性”和“可达空间大小”，挑最安全的走。
5. **重规划**：每个移动 tick 决策一次，吃到食物后立刻重新规划。

**验证方式**：


- 连续跑若干局，记录每局 AI 吃到的食物数与死因，确认存在连续吃满 15 个的完整记录。

## 八、两处关键逻辑，我用自己的话解释

**1. 贪吃蛇 AI 为什么能自动避开死路？**

如果只让它“朝食物的方向走”，蛇身一长就会把自己围死，因为它在接近食物时完全没有考虑吃完之后还能不能出来。我的做法是让 AI 每一步都先在脑子里把这条路线演一遍：它知道蛇每走一格尾巴也会跟着挪一格，所以会按“这一步吃没吃到食物”来决定尾巴弹不弹；演完之后，再检查从新的蛇头出发能不能绕回自己的尾巴——能追到尾巴，就说明身体还没被自己封死，这条路才敢走。要是食物根本走不到，或者走到了也出不来，它就退而求其次，在四个方向里挑一个能到达空间最大的走，先保命再说。

**2. 计分规则为什么这么定？**

AI 最初给的是“每吃一个食物加 10 分”，但这样长度 3 和长度 30 时吃一口得分一样，长蛇本来就更容易死，得分反而体现不出难度。我改成 `得分 += 10 × 吃到食物后的长度`：长度 3 吃到 4 得 40 分，4 吃到 5 得 50 分，越到后面每秒的操作压力越大、单口收益也越高，最高分才真正代表玩得好。

## 十、通用素养

**分支和合并**：分支就是从主线上分出一条支线，让你在不影响主线的前提下独立开发新功能；合并就是把支线上完成的改动汇总回主线。


**命令行与 Git 常用命令的用途**：

| 命令 | 用途 |
| --- | --- |
| `cd` | 切换当前所在目录，例如 `cd game/snake` 进入游戏目录 |
| `ls` | 列出当前目录下的文件和文件夹（Windows 的 PowerShell 里同样可用） |
| `mkdir` | 新建一个目录 |
| `git init` | 把当前目录初始化为 Git 仓库 |
| `git add` | 把修改暂存，准备提交 |
| `git commit` | 把暂存的内容提交成一个版本记录，并附上说明 |
| `git status` | 查看当前有哪些文件被修改、哪些已暂存 |
| `git log` | 查看历史提交记录 |
| `git branch` | 查看、创建分支 |
| `git switch` | 切换、创建分支 |
| `git merge` | 把一个分支的改动合并到当前分支 |
| `git push` / `git pull` | 把本地提交推送到远程仓库 / 把远程更新拉回本地 |

**为什么选 MIT 协议**：MIT 足够宽松，别人可以自由使用、修改、分发我的代码，只需要保留版权声明；对这个考核项目来说，我希望作品能被别人直接拿去学习和二次开发，MIT 是我最想要的效果，而且它短、好读，不需要额外解释。

## 十一、踩过的坑

1. **`git push` 不稳定 有时候频繁失败**：原因是 git 没走vpn。解决方法是用 `git config --global` 把 VPN 的端口配给 git，之后推送正常。
2. **分支从错误的位置分出去**：我在 `snake-game` 上做 AI 时，直接从 `snake-game` 分出了 `snake-ai`，形成 `main → snake-game → snake-ai` 的链式结构，而不是理想的主线 + 多条并列支线。后来把改动整理到 `snake-enhancement` 分支再合并回 `main`。
